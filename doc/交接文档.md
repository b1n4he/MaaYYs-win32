## 1. 项目概览

- **本项目**：[MaaYYs-win32](https://github.com/b1n4he/MaaYYs-win32)，[MaaYYs](https://github.com/TanyaShue/MaaYYs) 的分支，**仅面向阴阳师 Windows 官方桌面端**（阴阳师-MuMu模拟器专版，MuMu 引擎封装的 PC 客户端）。
- **上游**：TanyaShue/MaaYYs（资源 / 任务 / agent），通过 Win32 窗口控制（PrintWindow 截图 + SendMessage 后台点击）替代模拟器 / ADB。
- **本地路径**：
  - 源码仓库：`C:\Users\dick\Desktop\阴阳师\MaaYYs\MaaYYs-main`（git 仓库，main 分支）
  - 运行部署：`C:\Users\dick\Desktop\阴阳师\MaaYYs\MXU`（MXU 图形界面 + 运行时，**含用户配置，勿整目录覆盖**）
- **技术栈**：Go agent（1.24+，本机装 1.26.1）+ MaaFramework v5.13.0 + MXU v1.4.x；资源 JSON + 模板图 + ONNX 模型。

## 2. 仓库拓扑与分支约定

```
origin   -> https://github.com/b1n4he/MaaYYs-win32.git   （fork 自己的远端）
upstream -> https://github.com/TanyaShue/MaaYYs.git      （上游）
```

- 每次同步上游前建备份分支：`backup-before-v<版本>-sync`（已存在 v3.15 / v3.16 / v3.17 三代，可回滚）。
- 同步提交信息格式：`merge: sync upstream v<旧> -> v<新>`。

## 3. 上游同步 SOP（每次照做）

```powershell
git fetch upstream
git rev-list --count main..upstream/main        # 确认落后数
git branch backup-before-vX.Y-sync              # 备份
git merge --no-ff upstream/main
# 冲突处理原则见 §4，然后：
cd agent; go build -o agent.exe .; go vet ./...; go test ./...
# 全仓库 JSON 校验 + pipeline 模板图引用校验（815 个引用逐一存在）
git push origin main
```

**验证清单**：go build/vet/test 全过；所有 JSON 可解析；`pipeline/**/*.json` 的 template 引用均存在于 `resource_pack/*/image/`；interface.json 的 import 文件齐全；fork 分歧点（§4）未被上游覆盖。

## 5. 活动轮换维护（重点）

- **每月爬塔类活动**在 `resource_pack/base/pipeline/活动/每月周期/活动爬塔-<活动名>.json`，一个月一个文件（拾此一瞬、云华依言歌、武道大会……），随上游同步自动带上；任务入口是 `tasks/活动爬塔.json`。
- **`999` 是旧版通用爬塔任务**（`活动/限定/999.json` + `tasks/999.json`），靠 OCR 活动标题定位入口界面，标题随活动轮换变化：
  - 节点：`999-开始`、`999-开始挂机`、`手动999`、`999-手动战斗-识别是否返回爬塔界面` 四处 `expected`。
  - 当前值：`古迹演武|古跡演武|虚无精锐|虚无精銳`（古迹演武 = 2026-10 当前活动，本地加的；虚无精锐 = 上一期）。
  - **OCR 繁简变体坑**：同一画面 OCR 会随机返回繁体（实测「古跡演武」与「古迹演武」交替出现，score 都 ~0.88），新活动标题必须同时加繁简两种写法，否则会间歇性超时。
- **下次活动再轮换时**：若「自动999」又在入口 20 秒超时（特征：maafw.log 出现 `Task timeout [pretask.name=999-开始]` → `error handling loop detected`，debug_exports 的 on_error 截图正常但无标题），就把新活动标题加进这四个节点（保留旧值），或等上游官方适配后直接同步。
- 上游同步时要特别关注 **活动相关提交**（fix/feat 带活动名的），这是 fork 存在的主要意义之一。
- **每月活动流水线与游戏内当前活动错位时**（如 2026-10-10：拾此一瞬流水线 vs 游戏内已轮换古迹演武）：表现为「活动爬塔」任务提交后入口识别失败、掉进 导航-活动总览 循环空转，用户手动停止且任务显示 Succeeded（日志特征：OCR Failed 但 result 里能读到实际标题）。此时改用「自动999」（通用爬塔，标题 OCR 已兼容当前活动），等上游出 `活动爬塔-古迹演武.json` 后同步。

## 6. CI 与发布

- workflow：`build-release.yml`（仅此一个发包流）。触发：push 到 main（测试构建）/ 推 `v*.*.*` 形态 tag（正式发布）/ 手动。
- **发版操作**：`git tag v<interface版本>-<yyMMddHHmm>; git push origin <tag>`（fork 惯例带时间戳，避免与上游 tag 撞名）。产物：`MaaYYs-win32-win-<arch>-<tag>-MXU.zip` ×2（x86_64 / aarch64）。
- Android APK 默认只留 CI artifact；要随 Release 发布需仓库 Variables 设 `ANDROID_PUBLISH=true` 且配好签名 secrets（未验证过真机，谨慎开启）。
- `sync-upstream.yml`：每 6 小时 cherry-pick 上游**活动类提交**并自动打 tag 发布。
- `mirrorchyan*.yml`：指向上游 TanyaShue 仓库的 Mirror酱上传，**仅手动触发，勿开**（fork 已禁用 Mirror酱更新检查）。

## 7. 部署到本机 MXU（repo → MXU 目录）

```powershell
$repo = 'C:\Users\dick\Desktop\阴阳师\MaaYYs\MaaYYs-main'
$mxu  = 'C:\Users\dick\Desktop\阴阳师\MaaYYs\MXU'
# 先关闭 MXU（agent.exe 会被锁），然后：
robocopy "$repo\resource_pack" "$mxu\resource_pack" /MIR /NFL /NDL /NJH /NP
robocopy "$repo\tasks"   "$mxu\tasks"   /MIR /NFL /NDL /NJH /NP
robocopy "$repo\preset"  "$mxu\preset"  /MIR /NFL /NDL /NJH /NP
robocopy "$repo\assets"  "$mxu\assets"  /MIR /NFL /NDL /NJH /NP
Copy-Item "$repo\interface.json" "$mxu\" -Force
Copy-Item "$repo\agent\agent.exe" "$mxu\agent\" -Force   # 需先 go build
```

- **保留不动**：`config/`（用户任务配置）、`cache/`、`debug/`、`debug_exports/`、`Documents/`、`mxu.exe`、`maafw/`。
- robocopy 退出码 0-7 均为成功；≥8 才是失败。
- MXU 正在运行时 agent.exe 复制会报「文件被占用」——关掉 MXU 再复制。

## 8. 故障排查速查

- 日志导出：MXU 界面导出调试包 → `MXU/debug_exports/MaaYYs-logs-*`（含 maafw.log / agent log / config / on_error 截图）。
- 任务秒败/超时：看 maafw.log 中 `Task timeout` / `bad next` / `error handling loop detected` 的 node.name；对照 on_error 截图（截图全黑=PrintWindow 抓图失败；画面正常但超时=识别不匹配，多为活动 UI 变了）。
- on_error 截图文件名即失败节点名 + 时间。
- 部署端版本在 agent log 第一行（如 `"version":"v3.15.4"`）与 interface.json 的 version 可快速判断部署是否过期。
